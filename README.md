# Campus Bank

Учебный банк: React + TypeScript, FastAPI, PostgreSQL. Светлый интерфейс с жёлтыми акцентами, без градиентов. Клиенты, деньги и реквизиты вымышленные.

## Быстрый вход в панель управления

Нажмите жёлтый значок «C» семь раз подряд. Пауза между нажатиями — не больше одной секунды. Клик в другом месте, уход со страницы или потеря фокуса сбрасывают серию. Удержание Enter не заменяет семь отдельных нажатий. Название campus рядом с иконкой по-прежнему ведёт на главную.

Если вы уже вошли как администратор или сотрудник, откроется /staff. Иначе появится форма служебного входа. Если активен аккаунт клиента, сайт предложит явно выйти и сменить аккаунт. Жест не выдаёт роль и не обходит пароль; сервер проверяет доступ при каждом запросе.

На рабочем столе показаны самостоятельные регистрации, демо-профили, общее число клиентов и регистрации за сегодня по времени Бишкека. Все значения берутся из базы. Кнопка «Обновить статистику» заново запрашивает счётчики. Сотрудники и администраторы исключены; заблокированные клиенты учитываются. 45 демо-профилей не считаются самостоятельными регистрациями.

Для этого обновления новая миграция не требуется: достаточно заменить исходники и пересобрать приложение. Для перехода с версии до заявок нужна миграция 0002, как описано ниже.

## Обновление: регистрация, продукты и информация о банке

Открыта самостоятельная регистрация: /register создаёт клиента и один текущий счёт с нулевым остатком. Логин уникален, роль выбирается сервером. Пример учебной почты: name@campus.test. Отправка писем и SMS не используется.

Добавлены /products (9 продуктов и сервисов), /products/:id, /promotions, /about, /team, /contacts и форма заявки /apply/:id. Клиент видит заявки и ответы сотрудника в /bank/orders, сотрудники обрабатывают их в /staff/orders. При выполнении заявки на карту или счёт продукт действительно создаётся в базе. Сервисы уже доступны клиентам; заявки на них используются для консультации. Реальные карты, доставка и финансовые услуги не оформляются.

WhatsApp-поддержка: +996 220 715 205 и +996 995 393 911. Кнопки открывают чат по выбранному номеру; отправку сообщения подтверждает сам пользователь. Система не проверяет наличие WhatsApp-аккаунта у номера и не отправляет сообщения автоматически.

Сгенерированные изображения офиса, продуктов и команды включены в frontend/public/images/. Промты и назначение файлов описаны в docs/image-prompts.md. Имена и биографии руководства, команды и условия предложений являются частью вымышленного сценария.

### Обновление уже установленной версии

Сначала сохраните резервную копию базы. После замены исходников выполните `python backend/scripts/migrate.py` с владельческой строкой ADMIN_DATABASE_URL на своём компьютере. Новая миграция 0002 создаёт product_orders; существующие клиенты и операции сохраняются. Затем пересоберите и разверните приложение. Для Docker: `docker compose up --build -d`, затем `docker compose exec web python backend/scripts/migrate.py`. Повторный seed для обновления не требуется.

## Что реализовано

Личный кабинет, счета, выпуск и блокировка учебных карт, лимиты, переводы с подтверждением, платежи, история с фильтрами, CSV, печать квитанций, профиль, сеансы, поддержка, уведомления, рабочее место сотрудника и администратора. Генератор создаёт 45 клиентов со случайными паролями и согласованными проводками.

## Локальный запуск через Docker

1. Установите Docker Desktop. Из папки проекта выполните `docker compose up --build -d`.
2. Создайте таблицы: `docker compose exec web python backend/scripts/migrate.py`.
3. Создайте клиентов: `docker compose exec web python backend/scripts/seed_demo.py --output /tmp/client-access.csv`.
4. Скопируйте доступы на компьютер: `docker compose cp web:/tmp/client-access.csv ./client-access.csv`. Этот файл содержит пароли; храните отдельно от репозитория.
5. Создайте администратора: `docker compose exec web python backend/scripts/create_staff.py --username admin --name "Администратор" --role admin --output /tmp/admin-access.csv`.
6. Скопируйте доступ администратора: `docker compose cp web:/tmp/admin-access.csv ./admin-access.csv`.
7. Откройте http://localhost:8000 и войдите с выданными данными.

Для сотрудника поддержки повторите шаг 5 с логином support и ролью staff. Новые клиенты могут также зарегистрироваться самостоятельно через /register.

## Render Free + Neon Free

1. Создайте PostgreSQL в Neon. Сохраните строку подключения с TLS.
2. Загрузите исходники в свой GitHub-репозиторий, без .env и выгрузок паролей.
3. Создайте на Render Web Service, Language Docker, план Free. Используется корневой Dockerfile.
4. В Environment задайте DATABASE_URL, случайный APP_SECRET длиной минимум 32 символа, APP_ENV=production, COOKIE_SECURE=true, DEMO_QUICK_LOGIN=false, PUBLIC_BASE_URL=https://ваш-сервис.onrender.com и ALLOWED_HOSTS=ваш-сервис.onrender.com.
5. На своём компьютере установите Python 3.11+, создайте виртуальное окружение и установите `pip install -r backend/requirements.lock`.
6. Скопируйте .env.example в .env, заполните подключения и настройки. Не коммитьте этот файл. Выполните `python backend/scripts/migrate.py`, затем `python backend/scripts/seed_demo.py` и `python backend/scripts/create_staff.py --username admin --name "Администратор" --role admin`.
7. Откройте сайт и проверьте вход, перевод и квитанцию. Миграции и seed не выполняются при каждом перезапуске.

Для минимального запуска DATABASE_URL может временно совпадать с ADMIN_DATABASE_URL; перед соревнованием выделите приложению отдельную роль БД без прав изменения схемы. ADMIN_DATABASE_URL не передавайте в Render: это настройка компьютера преподавателя.

Free-сервис может засыпать и имеет квоты. Постоянные данные находятся во внешней PostgreSQL. 45 клиентов не являются гарантией работы 45 одновременно запущенных сканеров.

## Восстановление доступа

Клиент оставляет запрос на странице восстановления. Администратор выдаёт одноразовый код в своём кабинете и передаёт его клиенту отдельно. Срок действия — 15 минут. SMS и отправка писем не используются.

## Сброс раунда

На компьютере преподавателя: `python backend/scripts/export_round.py`, затем `python backend/scripts/reset_round.py --confirm RESET-CAMPUS-BANK`. Сброс удаляет банковские операции и обращения, пересоздаёт 45 клиентов, отзывает все сеансы, сохраняет служебные аккаунты и аудит. Новые пароли попадут в .private/client-access-new.csv. Сначала сохраняйте экспорт!

## Геоблокировка

По умолчанию выключена. Для прежнего сценария с зарубежным VPN подготовьте MMDB базу DB-IP, укажите GEOIP_DB_PATH, GEOBLOCK_ENABLED=true и список GEOBLOCK_DENY_COUNTRIES. Обязательно настройте доверенные прокси конкретного размещения и проверьте фактический клиентский IP. Неизвестная страна или отсутствующая база блокируют доступ. DB-IP требует атрибуцию. Блокировка страны не ограничивает доступ только студентами.

## Статус проверки

Фронтенд собран TypeScript/Vite. Серверные файлы проверены на синтаксис. Пять тестов серии нажатий прошли в Node.js. Десять интеграционных проверок регистрации, ролей, заявок, их повторной отправки, отмены, выпуска продукта и счётчиков регистраций прошли на PGlite с PostgreSQL-совместимым протоколом. Это отдельная тестовая среда: конкуренция транзакций и работа после размещения на обычном PostgreSQL/Neon требуют отдельной проверки. Браузерная проверка недоступна из-за ограничения запуска предпросмотра. Намеренные уязвимости в базовую версию не добавлялись.

Тесты: установите `pip install -e "./backend[dev]"`, задайте TEST_DATABASE_URL отдельной одноразовой тестовой PostgreSQL, примените к ней миграции и выполните `python -m pytest backend/tests`. Тесты очищают все прикладные таблицы тестовой базы; рабочую базу для этого не используйте.

Тесты последовательности нажатий: Node.js 22.18+; из frontend выполните `npm run test:shortcut`.
